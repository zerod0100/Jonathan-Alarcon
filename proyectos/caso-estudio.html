MicroPay

Migración de una arquitectura monolítica hacia microservicios en AWS

Proyecto técnico desarrollado para diseñar e implementar una arquitectura de microservicios utilizando servicios administrados de AWS, con foco en escalabilidad, disponibilidad, desacoplamiento y monitoreo.

← Volver al portafolio Ver proyecto técnico
01

Situación inicial

MicroPay es una aplicación fintech que inicialmente utilizaba una arquitectura monolítica. Esta estructura concentraba diferentes funcionalidades dentro de una misma aplicación, dificultando la escalabilidad independiente de cada componente.

Durante períodos de mayor utilización podían producirse cuellos de botella, ya que una funcionalidad que requería más recursos podía afectar el funcionamiento general de la aplicación.

Frente a esta situación se planteó una migración progresiva hacia una arquitectura basada en microservicios utilizando servicios administrados de AWS.

02

Desafío técnico

Escalabilidad

01 · Arquitectura

Permitir que los diferentes componentes de la aplicación puedan ejecutarse y escalarse de manera independiente.

Desacoplamiento

02 · Microservicios

Separar las funcionalidades principales de la aplicación para reducir la dependencia entre componentes.

Disponibilidad

03 · AWS

Utilizar servicios administrados de AWS para facilitar la ejecución, distribución y supervisión de los servicios.

03

Solución implementada

La solución consistió en dividir la aplicación en dos microservicios principales: Usuarios y Pagos.

Los servicios fueron empaquetados mediante Docker y almacenados en Amazon ECR. Posteriormente fueron ejecutados como tareas independientes utilizando Amazon ECS con AWS Fargate.

Para distribuir las solicitudes se implementó un Application Load Balancer, mientras que API Gateway funciona como punto de entrada para las solicitudes de la aplicación.

Finalmente, Amazon CloudWatch permitió centralizar los registros y facilitar el monitoreo básico de los servicios.

09

Impacto técnico

La implementación permitió transformar el enfoque monolítico inicial hacia una arquitectura distribuida basada en microservicios.

La separación de Usuarios y Pagos permite que cada componente pueda evolucionar de forma independiente, facilitando futuras mejoras y estrategias de escalamiento.

Además, la incorporación de API Gateway, Application Load Balancer y CloudWatch permitió establecer una estructura más organizada para el acceso, distribución y monitoreo de los servicios.

10

¿Por qué elegí este proyecto?

Elegí MicroPay como caso de estudio porque fue uno de los proyectos que me permitió integrar una mayor cantidad de conocimientos técnicos adquiridos durante el desarrollo del programa.

El proyecto combina desarrollo con Python, Docker, arquitectura de microservicios, servicios cloud, networking, balanceo de carga, contenedores y monitoreo.

También representó un desafío práctico, ya que fue necesario solucionar problemas reales relacionados con configuración de puertos, health checks, target groups, conectividad y comunicación entre servicios.

11

Conclusión

De una arquitectura monolítica a una solución cloud

El proyecto MicroPay representó una experiencia práctica de diseño e implementación de una arquitectura de microservicios sobre AWS. La solución permitió aplicar conocimientos de contenedores, networking, APIs, balanceo de carga y monitoreo.

Más allá de la implementación técnica, el proyecto fortaleció mi capacidad para analizar problemas, investigar soluciones y resolver dificultades durante el desarrollo de una infraestructura cloud.
