Proyecto de implementación de medidas básicas de seguridad cloud para la fintech Blue Wave, utilizando servicios disponibles en AWS Academy Learner Lab.

Mínimo privilegio

Situación inicial

La fintech Blue Wave migró su core bancario a AWS Academy Learner Lab. Una revisión preliminar detectó configuraciones débiles de seguridad y falta de monitoreo.

El reto consistió en aplicar medidas básicas de seguridad cloud, documentando la arquitectura y las evidencias de configuración.

Objetivo del proyecto

Aplicar principios básicos de seguridad cloud mediante la protección de datos en Amazon S3, la auditoría de eventos con AWS CloudTrail, la evaluación de cumplimiento mediante AWS Config y el monitoreo mediante Amazon CloudWatch.

Etapa 1 — Protección de datos e identidad

Se creó un bucket S3 para Blue Wave con configuraciones orientadas a evitar la exposición pública de información.

Configuraciones aplicadas

  • ACLs deshabilitadas.
  • Bucket owner enforced.
  • Bloqueo de las cuatro opciones de acceso público.
  • Cifrado SSE-S3.
  • Control de acceso mediante principios de mínimo privilegio.
blue-wave-cloud-secure1

Etapa 2 — Auditoría con AWS CloudTrail

Se configuró AWS CloudTrail para registrar las acciones realizadas dentro de la cuenta AWS y proporcionar trazabilidad sobre las operaciones realizadas.

Configuración

  • Trail: blue-wave-security-trail
  • Registro de eventos de administración.
  • Almacenamiento de registros en Amazon S3.
  • Separación entre datos protegidos y registros de auditoría.

Etapa 3 — AWS Config

AWS Config permitió evaluar automáticamente la configuración de los recursos y comprobar el cumplimiento de reglas de seguridad.

Configuraciones realizadas

  • Activación de AWS Config.
  • Registro de recursos.
  • Uso del AWS Config service-linked role.
  • Almacenamiento de información de configuración en S3.
  • Configuración de reglas de cumplimiento.
  • Revisión de estados COMPLIANT y NON_COMPLIANT.
COMPLIANT El recurso cumple la regla.
NON_COMPLIANT Existe una configuración que no cumple.

Etapa 4 — CloudWatch y alarmas

Se configuró Amazon CloudWatch para supervisar métricas relacionadas con el almacenamiento de Blue Wave y detectar condiciones que requieran atención.

Alarma configurada

BlueWave-S3-NumberOfObjects

Alarma orientada a detectar un crecimiento del número de objetos almacenados en el bucket.

Umbral: 100 objetos

Etapa 5 — Verificación del monitoreo

Se verificó la disponibilidad de las métricas de CloudWatch y el estado de la alarma configurada para el bucket S3.

Esta configuración permite detectar cambios importantes en el almacenamiento y facilita una respuesta preventiva ante comportamientos anómalos.

Etapa 6 — Verificación de cumplimiento

Finalmente se revisaron las reglas configuradas en AWS Config y sus resultados de evaluación.

Rule: s3-bucket-public-read-prohibited

Resource: serverless-por9

Compliance: COMPLIANT

Conclusiones

Cumplimiento mediante AWS Config

La implementación de AWS Config permitió automatizar la evaluación de la postura de seguridad de los recursos de Blue Wave. La validación mediante reglas transforma la revisión manual en un proceso continuo basado en estados de cumplimiento.

Detección mediante Amazon CloudWatch

La integración de alarmas métricas proporciona visibilidad operacional sobre el crecimiento del almacenamiento y permite identificar condiciones que requieren atención.

Seguridad de los datos

La configuración de Amazon S3 con bloqueo de acceso público, propiedad de objetos y cifrado SSE-S3 contribuye a reducir el riesgo de exposición de información almacenada.
